# 提示词参考手册（课后用）

> 配套讲稿 `presentation_final.md`。这份是**速查 + 复制即用**的提示词参考，不讲原理（原理见讲稿和 `ai_fundamentals_guide.md`）。

---

## 一、4 条核心原则（先记这个）

| 原则 | ❌ 常犯 | ✅ 改对 |
|------|--------|--------|
| **说清楚要什么** | 「写个函数」 | 「用 Python 写校验邮箱的函数，返回 True/False」 |
| **给点背景** | 「优化这段代码」 | 「这是 Flask 接口，执行 5 秒，帮我优化：[贴代码]」 |
| **复杂的拆开** | 「做个用户管理系统」 | 「先做注册接口，分四步：建表→模型→接口→测试，先做第一步」 |
| **设个角色** | 「看看这段代码」 | 「你是资深 Python 后端，帮我审查这段代码的安全和性能」 |

**第 5 条补充：给示例。** 想要特定格式时，给 1–2 个输入输出示例，比描述半天都管用：
```
格式化手机号：输入 "13812345678" → 输出 "138-1234-5678"
```

> 一句话：**Garbage in, garbage out。** 你输入的质量，决定它输出的质量。

## 二、好提示词的骨架

复杂任务，按这个结构组织，几乎不会跑偏：

```
【角色】你是……（资深后端 / 需求分析师 / ……）
【任务】帮我……（一句话目标）
【背景/上下文】我在做……，用的是……（项目、技术栈、约束）
【要求】1. …… 2. …… 3. ……（具体要求，分条列）
【输出格式】请输出……（表格 / 代码 / 文档结构）
【示例】输入 X → 输出 Y（可选，想要特定格式时给）
```

不一定每次都写全，但**任务、背景、要求**这三样尽量别省。

## 三、模板库（复制即用）

### 模板 1：写代码（开发）

```
你是资深 Python 后端工程师。
帮我实现：[功能描述，如"校验邮箱格式的函数 validate_email(email:str)->bool"]

要求：
1. 用 [正则/标准库] 实现
2. 非法输入返回 False，不抛异常
3. 加中文文档字符串和 2 个使用示例
4. 加类型注解

技术栈：[如 Python 3.10]
```

### 模板 2：重构代码（开发）

```
帮我重构下面这段代码：
[贴代码]

当前问题：[如"有重复逻辑/函数太长/硬编码"]

重构要求：
1. 遵循 DRY 原则，抽取重复
2. 保持功能不变
3. 加类型注解和注释
4. 给出重构前后对比 + 改进点说明
```

### 模板 3：生成单元测试（开发）

```
帮我为 [文件/函数名] 生成 pytest 单元测试：
[贴代码 或 @文件路径]

要求：
1. 覆盖所有公共方法
2. 包含正常、异常、边界三种场景
3. 测试用例独立，不依赖执行顺序
4. 包含测试数据准备
```

### 模板 4：分析 Bug（开发）

```
帮我分析这个报错并修复：

错误信息：[贴报错/堆栈]
相关代码：[贴代码 或 @文件路径]
重现步骤：1. …… 2. ……

请给出：1. 错误原因  2. 修复方案（直接改代码）  3. 怎么避免再犯
```

### 模板 5：整理需求（业务顾问）

```
帮我把下面这段业务方的话，整理成结构化需求：

原话："[贴业务方原话]"

请输出：
1. 功能点（分条列）
2. 每个功能怎么算做完了（验收点，要具体可验证）
3. 优先级建议（Must / Should / Could / Won't）
```

### 模板 6：写文档/会议纪要（业务顾问）

```
帮我整理[会议/需求评审]纪要：

内容：[贴录音转写 / 笔记要点]
参会人：[列出]

请输出：
1. 会议摘要（3–5 句）
2. 行动项列表（事项 / 责任人 / 截止时间）
3. 风险和待决问题
4. 后续跟进计划
```

## 四、常见坑 & 解法

| 坑 | 表现 | 解法 |
|----|------|------|
| 提示词太模糊 | 「优化代码」「写个函数」AI 反问或瞎猜 | 写清目标、语言、约束 |
| 没给上下文 | AI 给的方案对不上你的项目 | 说清项目背景、技术栈、约束 |
| 一次要太多 | 「做个完整电商系统」AI 迷路 | 拆步骤，一次一个小目标 |
| 没指定输出格式 | AI 啰嗦一大段 | 明确要"表格/代码/分条"，必要时给示例 |
| 对话太长 AI 忘事 | 前后矛盾、忘了早期约定 | 重要规则放 CLAUDE.md/系统提示，或开新对话重发背景 |

## 五、写完先自查（清单）

- [ ] 目标说清楚了吗？（要什么）
- [ ] 背景给够了吗？（项目、技术栈、约束）
- [ ] 复杂任务拆成步骤了吗？
- [ ] 输出格式指定了吗？
- [ ] 想要特定格式的话，给示例了吗？

**全勾了再发。** 发完看结果，不满意就**调整提示词再发**——迭代几轮很正常，别指望一次完美。

---

## 六、一个心法

提示词不是"一次写对"的技术，是"快速试、快速调"的技术。
**先给一版 → 看结果 → 调提示词 → 再给一版**，比憋半天想完美提示词高效得多。

想让 AI 改它自己的输出，直接说：「上面这段太啰嗦，精简成 3 条要点」「这个方案没用上 X，重做」——它改得比人快。
