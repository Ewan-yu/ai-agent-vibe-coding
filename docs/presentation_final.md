## 幻灯片 3：AI 智能体是什么

**一句话：大模型 + 会用工具 + 有记忆 + 会规划**

- **大模型**：听得懂人话，会推理、会写东西
- **工具**：能调接口、读写文件、跑命令（不只是回文字）
- **记忆**：记得住刚才聊了啥、项目长啥样
- **规划**：复杂任务能自己拆步骤、一步步做

**打个比方**：
- 以前的 AI = 一本百科全书（你问它答，答完就完）
- 现在的 AI 智能体 = 一个能动手的助理（你说，它去做，做完给你看）

> 【讲师备注】这页是地基，用"百科全书 vs 助理"这个对比让所有人秒懂。不要展开讲技术细节，后面案例会自然印证。

## 幻灯片 4：AI 是怎么"听懂"你说话的

**核心就一件事：注意力机制——它知道一句话里哪些词更重要。**

- 你说"我今天去超市买了苹果"，它知道重点是"超市"和"苹果"，而不是"我今天去"
- 同一个"苹果"：
  - "苹果很好吃" → 水果
  - "苹果手机很贵" → 品牌
  - 靠**上下文**判断，不是死记硬背

**所以结论很朴素：你给的上下文越清楚，它理解得越准。**

> 【讲师备注】原理只讲这一页，不展开 Transformer、不贴权重数字（那些数字既不准也把人讲困）。记住一个比喻：AI 像人读书一样，会自动盯重点。重点是为后面"提示词要给足上下文"做铺垫。

## 幻灯片 5：AI 大模型的输入输出结构

**输入是什么、输出是什么——本质就三类消息在轮流：**

| 类型 | 是谁 | 干嘛的 |
|------|------|--------|
| **System**（系统提示） | 你给 AI 的"岗位说明书" | 定角色、定边界、定规矩（全程有效） |
| **User**（用户消息） | 你每次问的话 | 提任务、给上下文 |
| **Assistant**（助手消息） | AI 的回答 | 它干完活给你的结果 |

**System Prompt 最容易被忽略，但最值钱**：同样一句"帮我写个函数"，
- 不设角色 → AI 反问"你要啥语言？啥功能？"
- 设了"你是 Python 后端工程师" → AI 直接按 Python 后端的套路来

**还有一个绕不开的常识：上下文窗口（Context Window）**

- AI 一次能"看到"的信息是有**上限**的（系统提示 + 全部历史对话 + 当前输入，加起来不能超）
- 超过了会怎样？**最早的内容会被"挤出去"，AI 就"忘"了**——就像人的短期记忆，塞满了新的、旧的就掉
- 量级概念：现在的模型动辄几十万到上百万 token（1 个汉字 ≈ 1–2 个 token），看着很大，但**长对话、大项目照样会撑满**

**实操结论（重要）**：
- 对话一长，AI 开始"前后矛盾""忘了之前说的" → 把重要信息放进系统提示 / CLAUDE.md，或干脆**开新对话**重发背景
- 别把整个大文件无脑塞进去 → 给**相关的**那部分就够

> 【讲师备注】上下文窗口是理解 AI 很多"怪行为"的根子：为什么 AI 会忘事、会前后矛盾，都在这。讲透这点，后面 CLAUDE.md、开新对话这些操作就都有依据了。在 Claude Code 里，System Prompt 不用手动塞——项目根目录的 `CLAUDE.md` 就是干这个的（下一部分讲）。

## 幻灯片 6：怎么写好提示词（一）——4 条原则，每条都配正反对比

**和 AI 沟通，记住这 4 条。每条左边是常犯的错，右边是改对的样：**

**1. 说清楚要什么**
- ❌「写个函数」
- ✅「用 Python 写一个校验邮箱格式的函数，返回 True/False」

**2. 给点背景**
- ❌「优化这段代码」
- ✅「这是 Flask 接口，每次执行要 5 秒，帮我优化性能：[贴代码]」

**3. 复杂的拆开讲**
- ❌「帮我做个用户管理系统」
- ✅「先做注册接口，分四步：建表 → 模型 → 接口 → 测试，请先做第一步」

**4. 让它演个角色**
- ❌「看看这段代码」
- ✅「你是资深 Python 后端，帮我审查这段代码的安全性和性能」

**一句话：Garbage in, garbage out——你输入的质量，决定它输出的质量。**

> 【讲师备注】这页是"原则 + 微对比"，每条配一个一眼看懂的正反例子，比纯讲口诀好记。下一页给一个完整实例，看这 4 条怎么一起用。

## 幻灯片 7：怎么写好提示词（二）——一个完整实例 + 业务侧同理

**把上一页 4 条一起用，差异非常明显：**

**❌ 坏提示词**
```
帮我写个校验函数
```
问题：校验什么？什么语言？返回啥？出错怎么办？——AI 只能反问或瞎猜。

**✅ 好提示词**
```
用 Python 写一个校验邮箱格式的函数 validate_email(email: str) -> bool：
- 用正则实现
- 非法输入（空、None、格式错）返回 False，不要抛异常
- 加中文文档字符串和 2 个使用示例
```

**差异就在这几样**（正好对应上一页 4 条）：

| 要素 | 坏 | 好 |
|------|----|----|
| 目标 | 模糊"校验函数" | 明确"校验邮箱格式" |
| 约束 | 无 | 语言、参数、返回值、异常处理 |
| 示例 | 无 | 要求附 2 个示例 |

**业务侧完全同理**：
- ❌「帮我整理需求」
- ✅「帮我把下面这段业务方的话整理成功能点和验收点：[贴原话]」

> 【讲师备注】这页和上一页是同一主题连续讲：上一页 4 条原则配微对比，这页一个完整实例 + 业务侧。强调"角色 + 目标 + 约束 + 示例/背景"这套打法，业务和开发通用。

## 幻灯片 8：从"提示词工程"到"上下文工程"——还要当心"上下文衰减"

**用一阵子你会发现：光把单次提示词写好，还不够。**

**两者关注的事不一样：**

| 维度 | 提示词工程 | 上下文工程 |
|------|-----------|-----------|
| 关注 | 这一次怎么问好 | 整个对话/项目该喂什么 |
| 时间尺度 | 单次提问 | 多轮、长任务 |
| 手段 | 角色、清晰、分步、示例 | 系统提示、CLAUDE.md、对话管理、外部知识、压缩 |
| 典型问题 | 问得模糊，答得跑偏 | AI 忘事、前后矛盾 |

**还要特别当心：上下文衰减（Context Decay）**

- **就算没超出窗口**，对话一长，AI 对**最早内容**的注意力也会下降——早期定的规则、给的背景，慢慢就"不管了"
- 和上下文窗口的区别：
  - **窗口**是硬限制——超了，内容直接被挤出去丢掉（前面幻灯片 5 讲的）
  - **衰减**是软现象——没超，但早期信息的影响力越来越弱
- 表现：忘了开头设的角色、前后说法不一致、早期约束被忽略
- 应对三条：
  1. 重要规则放系统提示 / CLAUDE.md（让它每次都在"视线"里）
  2. 长任务定期"复述"关键背景，或干脆**开新对话**重发
  3. 这正是 Claude Code 帮你**自动管理上下文**的价值

> 【讲师备注】这页一次讲清"演进 + 衰减"。上下文衰减是前面（幻灯片 5）上下文窗口的延伸，两个概念别混：窗口=硬限制（超了丢），衰减=软现象（没超也会变弱）。这页也是原理到工具的桥梁——Claude Code 的核心价值之一，就是替你对抗衰减、管理整个上下文。

## 幻灯片 9：一条最重要的认知

**AI 是"大概率"生成，不是"查数据库"。**

- 同一个问题，问两遍，答案可能不一样
- 它会**一本正经地胡说**（看起来很专业，其实是编的）
- 所以——

**它写的代码、给的结论，一定要自己复核、跑一遍。**
**AI 是帮你提速的，不是替你负责的。**

> 【讲师备注】这页是整场分享的"安全带"。很多翻车都是因为把 AI 当搜索引擎用、直接复制上线。讲完这页，后面案例里"为什么写完要跑测试"就顺理成章了。

## 幻灯片 10：什么是 Vibe Coding（课程点个题）

**咱们标题里的"Vibe Coding"，到底是什么？**

- **提出者**：Andrej Karpathy（OpenAI 联合创始人），2025 年 2 月首次提出
- **一句话**：**自然语言成了编程语言**——你用大白话描述要什么，AI 自动生成、测试、改代码，你只管整体逻辑和"感觉"（Vibe）

**三个最关键的特征：**

1. **说话即编程**：不用逐行写语法，说"做个类似 XX 的页面"，它搭架构、填代码
2. **先跑通，再优化**：接受 AI 代码里的小瑕疵，**用自然语言反馈让 AI 修**，而不是手动改 bug
3. **门槛骤降**：非专业也能几分钟出一个能跑的原型（MVP），适合快速验证想法

**一句话点睛**：开发者从代码"打字员"变成"指挥官"。

> 【讲师备注】概念点到为止，别展开风险/维护那些（和上一页安全带、案例④的"贴报错自修"已经覆盖了"要保质"的立场，别重复说教）。讲这页时口头带一句衔接即可：① "先跑通、用自然语言让 AI 修" 正好呼应上一页"AI 会犯错要复核"——Vibe Coding 不是放任质量，是换个方式保质。② Karpathy 2026 年进一步提的 **Agentic Engineering（代理工程）**，就是从"凭感觉"升级到"指挥多个 AI agent 系统化协作"——这正是下一页 Claude Code 这类工具的方向，紧接着讲。

## 幻灯片 11：Claude Code 不只是"又一个聊天框"

**上一页说的 Vibe Coding，Claude Code 就是干这个的工具。**

**它和网页版 AI 最大的区别：它会动手。**

| 网页版 AI | Claude Code |
|-----------|-------------|
| 你问，它答一段文字 | 它能**直接改你的文件、跑你的命令** |
| 代码要你自己复制粘贴回去 | 它在项目里**自己读写、自己执行** |
| 每次重新开始 | 它**记得这个项目的结构、规范、上下文** |

**所以用法完全不同**：不是"问一句拿一段代码"，而是"说个目标，让它在你项目里干完、跑通"。

> 【讲师备注】这是工具部分的核心认知。把上一页的 Vibe Coding 概念落到具体工具上：Claude Code 就是让你能用大白话指挥、它在真实代码里落地的那类 agent。很多人装了却当 ChatGPT 用，浪费了。这页要让开发同学尤其眼前一亮。

## 幻灯片 12：用之前先做一件事——写 CLAUDE.md

**在项目根目录放一个 `CLAUDE.md`，AI 每次干活都会先读它。**

相当于给新来的助理写一份"项目须知"：

```markdown
# 项目说明
内部员工信息管理系统（Python + Pydantic）。

# 技术栈
- Python 3.10+，Pydantic v1，pytest

# 规范
- 函数要有类型注解和文档字符串
- 注释和报错信息用中文

# 常用命令
- 跑全部测试：pytest tests/ -v
- 跑单个文件：pytest tests/test_user_service.py -v
```

**好处**：不用每次都重复交代技术栈、规范、怎么跑测试，AI 自动就按规矩来。

> 【讲师备注】这是"提效第一步"，也是最容易落地的干货。现场可以打开这个项目的 CLAUDE.md 给大家看一眼（没有就当场 `claude` 里输入 `/init` 让它生成一个）。

## 幻灯片 13：跟 AI 协作的正确姿势

**小步快跑，别一口气甩大需求。**

1. 先让它搭个**最小骨架**，跑通
2. 再加一个功能，跑通
3. 出错了？**把报错原样贴回去**，让它自己读、自己改
4. 跑通了，再加下一个

**关键心法：让它自己读报错，比你手动描述问题快十倍。**
你不需要看懂每一行错误，复制粘贴回去就行。

> 【讲师备注】这页是"实操心法"。后面案例的第④段（迭代纠错）就是演示这个——故意触发一个错，把报错贴回去，看 AI 自己修。这是日常用 AI 写代码最真实的场景。

## 幻灯片 14：贯穿案例——员工信息管理加"按部门"

**场景（业务顾问和开发都熟悉）：**
> 我们有个内部员工信息管理的小系统（就是本项目的 `user_service.py`）。
> 现在员工多了，业务方提了个需求：**想能按部门看人，新来的员工能批量录进去。**

**现状**：系统里压根没有"部门"这个概念。

**接下来分四段演**，业务顾问负责前两段，开发负责后两段——但**是同一个需求一路打通**：

| 段 | 谁来 | 干啥 |
|----|------|------|
| ① 需求澄清 | 业务顾问 | 把业务方一句话，整理成清楚的需求 + 验收点 |
| ② 文档产出 | 业务顾问 | 一键生成需求说明 / 用户故事 |
| ③ 功能实现 | 开发 | 用 Claude Code 给模型加"部门"、加筛选和批量导入 |
| ④ 迭代纠错 | 开发 | 出错了，贴报错让 AI 自修，跑通 |

> 【讲师备注】这页是案例的"目录"，先让大家知道接下来要干什么。强调：这不是四个孤立的 demo，是同一个需求从业务到代码打通，所以前后是连着的。

## 幻灯片 15：案例①需求澄清（业务顾问段）

**输入（业务方原话，就这么随意）：**
> "我们想能按部门看人，新来的能一批批录进来，别一个个填。"

**对 AI 说：**
```
帮我把下面这段业务方的话，整理成清楚的功能需求和验收点。
原话："我们想能按部门看人，新来的能一批批录进来，别一个个填。"
请输出：1) 要做的功能点  2) 每个功能怎么算做完了（验收点）
```

**AI 输出（约）：**
- 功能1：按部门筛选员工 → 验收：选"研发部"能列出该部门所有人
- 功能2：批量导入员工 → 验收：一次传多条，成功的入库、失败的报原因
- 功能3：员工要有"部门"字段 → 验收：每个员工都能标记所属部门

> 【讲师备注】业务顾问同学重点看这页。价值：把一句模糊的人话，30 秒变结构化需求。不需要记任何格式术语，AI 自己会给。

## 幻灯片 16：案例②文档产出（业务顾问段）

**接着上面，再对 AI 说：**
```
基于上面整理的需求，帮我写一份简短的需求说明，
并给出 3-5 条用户故事（作为…我想要…以便…）。
```

**AI 直接产出**：需求说明（功能/非功能）+ 用户故事清单，**可以直接贴进 wiki / 需求文档**。

**业务顾问的收获**：
- 会议纪要、需求文档、用户故事、验收标准——这些"体力活"都能让 AI 出初稿
- 你从"从零写"变成"改和审"，**省下的是最耗时的那部分**

> 【讲师备注】强调"从零写 → 改和审"这个角色转变，这是 BA/业务顾问用 AI 最大的价值点。课后参考文档里有会议纪要、竞品分析等现成模板。

## 幻灯片 17：案例③功能实现（开发段，agent 演示）

**开发同学接手，打开 Claude Code，目标是给系统加"按部门"能力。**

**第一句指令：**
```
我要给员工系统加"部门"概念。现在 User 模型在 src/models/user.py，
请：1) 给 User 和 UserCreate 加一个 department 字段（字符串，默认"未分配"）
2) 在 UserService(src/services/user_service.py) 加 get_users_by_department 方法
```

**接下来你会看到**：AI 自己读文件、改代码、**自己跑测试**、把结果告诉你——**全程不用你切换窗口**。

> 【讲师备注】这是 Claude Code 的"高光时刻"，和网页版对比最强烈的一页。现场真跑（演示脚本里有兜底录屏）。强调：一句自然语言，它在真实代码里落地——这就是 Vibe Coding。

## 幻灯片 18：案例④迭代纠错（开发段，贴报错自修）

**现实里 AI 不会一次完美。比如批量导入时，遇到重复用户名，`create_user` 会抛 `ValueError`，第一批代码没处理，测试挂了。**

**你不需要自己 debug，把报错原样贴回去：**
```
跑批量导入测试时报错了：
ValueError: 用户名已存在
在 test_batch_import_users 里。
帮我改 batch_import_users：重复的跳过、收集起来返回，
不要因为一条失败整个挂掉。然后重新跑测试。
```

**AI 自己读报错、自己改、自己重跑测试，直到通过。**

**这就是日常用 AI 写代码的真实节奏：**
给目标 → 跑 → 错了贴回去 → 它修 → 再跑 → 通了。

> 【讲师备注】这页最"接地气"。很多人以为用 AI 是"一次成型"，其实 80% 的时间是在这第④段——来回纠错。让 AI 自己读报错，比人去翻译错误快得多。这也是为什么前面强调"AI 会犯错，所以要跑测试"。

## 幻灯片 19：三句话回顾

1. **原理**：AI 靠"注意力"抓重点，**你给的上下文越清楚，它越准**；但它是概率生成，**会犯错，结果一定要复核**。
2. **工具**：Claude Code 是会动手的 agent，不是聊天框。**先写 CLAUDE.md，再小步快跑、贴报错让它自修。**
3. **用法**：业务顾问把"从零写"变成"改和审"；开发把"一句大白话"变成"真实代码落地"。

**一句话总结：AI 不替你负责，但能把最耗时的体力活接过去。**
