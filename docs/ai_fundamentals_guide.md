## 一、AI 是怎么"读懂"你说话的：注意力机制

### 一句话

AI 读一句话时，会**自动判断哪些词更重要、哪些词之间有关联**——这套机制叫"注意力机制"。这是大模型能"理解"语言、而不是死记硬背的关键。

### 生活化理解

想象你在读一篇长文章：
- 你的眼睛会**自动跳过废话，盯住关键词和关键句**
- 你能根据上下文猜出一个生词的意思

AI 的注意力机制干的就是这件事：
- 它会"关注"输入里**最相关的部分**，而不是平等对待每个字
- 所以它能抓住重点、处理长文本、做推理

### 一个最直观的例子：多义词

同一个"苹果"，AI 靠**上下文**判断含义：

| 句子 | AI 的理解 |
|------|----------|
| "苹果很好吃" | 水果（关注"好吃"） |
| "苹果手机很贵" | 品牌（关注"手机""贵"） |
| "我买了个苹果" | 需要更多上下文才能定 |

**关键结论：你给的上下文越清楚，AI 理解得越准。** 这就是为什么提示词要"给背景"。

### 为什么这对"用 AI"很重要

注意力机制解释了 AI 的几个行为：
- **能理解代词指代**（"它""那个"指什么）
- **能处理长文本**、抓住重点
- **能做简单推理和因果判断**
- **同一个问题，不同问法，答案质量差很多**——因为 AI 关注的重点被你引导了

## 二、Token：AI 眼里的"字"

AI 不是按"字"或"词"处理文本，而是按 **token**（标记）：
- 一个 token 可能是一个字、一个词、或半个词
- 粗略换算：**1 个汉字 ≈ 1–2 个 token**；1 个英文单词 ≈ 1 个 token

了解 token 是因为——**上下文窗口是按 token 算的**。

---

## 三、上下文窗口：AI 一次能"看"多少

### 是什么

AI 一次能"看到"的信息有**上限**，叫上下文窗口：
```
上下文 = 系统提示 + 全部历史对话 + 当前输入
```
加起来不能超过窗口大小。

### 超了会怎样

**最早的内容会被"挤出去"，AI 就"忘"了**——像人的短期记忆，塞满新的、旧的掉。

现在的模型窗口动辄几十万到上百万 token，看着很大，但**长对话、整个大项目，照样会撑满**。

### 量级感觉

- 几万字的文章、一两百行代码、十几轮对话——一般没问题
- 一整本书、整个大型代码库、上百轮长对话——会超

## 四、上下文衰减：没超也会"忘"

这是比"窗口"更隐蔽、也更常踩的坑。

### 是什么

**就算没超出窗口**，对话一长，AI 对**最早内容**的注意力也会下降——早期定的规则、给的背景，慢慢就"不管了"。

### 和窗口的区别（别混）

| | 上下文窗口 | 上下文衰减 |
|---|-----------|-----------|
| 性质 | **硬限制** | **软现象** |
| 触发 | 内容总量超了 | 对话变长（哪怕没超） |
| 表现 | 早期内容直接被丢 | 早期内容还在，但影响力变弱 |
| 你看到的 | AI 彻底"失忆" | AI 前后矛盾、忘了早期约定 |

### 实操应对

1. **重要规则放系统提示 / CLAUDE.md**——让它每次都在 AI 的"视线中央"，不会被衰减
2. **长任务定期"复述"关键背景**，或干脆**开新对话**重发
3. 这正是 Claude Code 这类工具的价值：它帮你**自动管理上下文**（读项目、记规范、按需取文件）

---

## 五、所以，用 AI 时记住这几条

| 原理 | 对你的意义 |
|------|-----------|
| 注意力机制靠上下文 | **提示词要给足背景**，别让 AI 猜 |
| 上下文窗口有上限 | 别无脑塞整个大文件；长对话会撑满 |
| 上下文衰减 | 重要信息放 CLAUDE.md/系统提示；长任务开新对话 |
| AI 是概率生成 | 同一问题答案可能不同、会胡说，**结果要复核** |

**一句话**：理解这些原理，不是为了考试，是为了**知道什么时候该给 AI 补上下文、什么时候该开新对话、什么时候必须自己复核**——这些判断对了，用 AI 就顺了。
