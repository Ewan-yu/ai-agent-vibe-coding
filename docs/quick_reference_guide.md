## 二、业务顾问常用提示词

### 整理需求
```
把下面这段业务方的话整理成结构化需求：
原话："[贴原话]"
输出：1) 功能点  2) 每个功能的验收点  3) 优先级（Must/Should/Could/Won't）
```

### 梳理业务流程
```
梳理[流程名]，当前流程：[描述步骤]
输出：1) 当前流程图（文字版） 2) 痛点 3) 优化建议 4) 优化后流程
约束：[如需支持手机号、防恶意注册等]
```

### 会议纪要
```
整理[会议名]纪要，内容：[贴笔记/录音转写]，参会人：[列出]
输出：1) 摘要 2) 行动项（事项/责任人/截止） 3) 风险待决 4) 跟进计划
```

### 写需求文档
```
为[功能名]写需求规格说明书，功能需求：[...]，非功能需求：[...]
输出：1) 功能需求列表 2) 非功能需求 3) 数据字典 4) 验收标准
```

### UAT 测试用例
```
为[功能名]写 UAT 测试用例，验收标准：[...]
输出：正向/反向/边界三类用例 + 测试数据
```

### 竞品分析
```
对[产品/功能]做竞品分析，竞品：[列出]，维度：功能/体验/技术/商业
输出：竞品对比表 + 最佳实践 + 改进建议 + 优先级
```

## 三、开发常用提示词

### 写代码
```
你是资深 Python 后端。帮我实现：[功能]
要求：1) 用[库]实现 2) 非法输入不崩 3) 加文档字符串和示例 4) 类型注解
技术栈：[Python 3.10 + ...]
```

### 重构代码
```
重构下面代码，问题：[重复/太长/硬编码]
[贴代码 或 @文件路径]
要求：抽取重复、保持功能、加注释，给重构前后对比
```

### 生成单元测试
```
为 [函数/文件] 生成 pytest 测试：[@文件路径]
要求：覆盖所有公共方法，含正常/异常/边界，用例独立
```

### 分析 Bug（最常用）
```
报错信息：[贴报错]
相关代码：[贴代码 或 @文件路径]
请：1) 分析原因 2) 直接给修复代码 3) 怎么避免再犯
```

### 解释代码
```
解释 @src/services/user_service.py 里 [类/函数] 的功能和设计，并评估代码质量
```

## 四、Claude Code 命令速查

| 操作 | 命令 / 写法 |
|------|------------|
| 进交互模式（多轮，推荐） | 终端输入 `claude` |
| 单次问答（出结果即退出） | `claude -p "你的提示词"` |
| 引用项目文件 | 提示词里写 `@src/models/user.py` |
| 生成 CLAUDE.md | 进 `claude` 后输入 `/init` |
| 让它跑测试 | 直接说「跑一下 pytest tests/ -v」它会自己执行 |
| 出错了怎么办 | **把报错原样贴回去**，让它自己读、自己改 |
| 换个新开始 | 输入 `/clear` 清上下文，或直接关掉重开 |

**两种模式怎么选**：
- 业务顾问出文档/整理需求 → 单次 `claude -p "..."` 就够
- 开发改代码/跑测试/纠错 → 用交互式 `claude`，多轮 agent

## 五、常见问题速答

| 问 | 答 |
|----|----|
| AI 输出质量怎么提高？ | 给足上下文、拆步骤、设角色、给示例（4 条） |
| 生成的代码能直接用吗？ | 当草稿，**必须复核 + 跑测试** |
| 对话一长 AI 就忘事？ | 重要信息放 CLAUDE.md，或开新对话重发背景 |
| AI 答错了怎么办？ | 调提示词再发，或把错误贴回去让它改，别手动硬改 |
| 哪些场景最适合？ | 业务：整理需求/纪要/文档；开发：写码/重构/测试/查 Bug |

---

## 六、一个心法

**先给一版 → 看结果 → 调提示词 → 再给一版。** 迭代比憋完美提示词高效。
想让 AI 改自己的输出，直接说「太啰嗦，精简成 3 条」「没用上 X，重做」——它改得比人快。
