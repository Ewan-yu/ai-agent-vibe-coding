## 第一部分：AI 原理（幻灯片 3–9）

讲明白"AI 怎么工作"，**只讲本质，不堆术语和伪细节**。

| 页 | 主题 | 核心一句话 |
|----|------|-----------|
| 3 | AI 智能体是什么 | 大模型 + 工具 + 记忆 + 规划；从"百科全书"到"能动手的助理" |
| 4 | 注意力机制 | AI 像人读书一样自动盯重点；给足上下文它才准（不展开 Transformer、不贴权重数字） |
| 5 | 输入输出结构 + 上下文窗口 | 三种消息（System/User/Assistant）；窗口有上限，超了会被"挤出去遗忘" |
| 6 | 提示词原则（一） | 4 条原则，每条配正反对比：说清楚 / 给背景 / 拆步骤 / 设角色 |
| 7 | 提示词原则（二） | 一个完整好坏对比 + 业务侧同理 |
| 8 | 提示词工程 → 上下文工程 | 单次写好不够；**上下文衰减**（没超窗口也会忘早期的） |
| 9 | 认知安全带 | AI 是概率生成，会一本正经胡说，**结果必须复核/跑测试** |

> 关键衔接：第 9 页的"要复核"→ 案例④的"贴报错自修"一脉相承。

## 第二部分：工具（幻灯片 10–13）

| 页 | 主题 | 核心一句话 |
|----|------|-----------|
| 10 | 什么是 Vibe Coding（点题） | Karpathy 2025.2 提出；自然语言成编程语言；从"打字员"到"指挥官" |
| 11 | Claude Code 不只是聊天框 | 它会动手：自己读写文件、跑命令、记得项目上下文 |
| 12 | 先写 CLAUDE.md | 给 AI 一份"项目须知"，不用每次重复交代技术栈/规范 |
| 13 | 协作姿势 | 小步快跑；出错把报错贴回去让它自修 |

> Vibe Coding 的"接受瑕疵"不是放任质量，是**用自然语言让 AI 修**——和案例④呼应。材料里 Karpathy 2026 的 Agentic Engineering（指挥多个 agent 协作）可在讲第 10 页时口头带一句，引出 agent 工具。

## 第三部分：贯穿案例（幻灯片 14–18）

**一个需求打通业务顾问和开发，不是四个孤立 demo：**

> 场景：给本项目 `user_service.py`（员工信息管理）加"按部门筛选 + 批量导入"。现状：系统没有"部门"概念。

| 页 | 段 | 谁来 | 动作 |
|----|----|------|------|
| 14 | 背景 | — | 案例介绍 + 四段目录 |
| 15 | ① 需求澄清 | 业务顾问 | 业务方一句大白话 → 结构化需求 + 验收点 |
| 16 | ② 文档产出 | 业务顾问 | → 需求说明 + 用户故事（"从零写"变"改和审"） |
| 17 | ③ 功能实现 | 开发 | Claude Code agent 加 department 字段、加方法、自己跑测试 |
| 18 | ④ 迭代纠错 | 开发 | 故意触发 `ValueError`，贴报错让 AI 自修 |

> 案例基于真实代码（`User` 模型无 department 字段；`create_user` 重复检查抛 `ValueError`），现场能真跑。详细操作见 `demo_scripts.md`。

## 演讲注意事项（精简）

1. **环境必验**：上台前 `pytest tests/ -v` 必须全绿（否则案例③④没法演）；`claude` 可用、联网。
2. **录屏兜底**：案例③④提前录屏，网络/AI 卡顿时直接切录屏，别台上干等（见 `demo_scripts.md`）。
3. **时间不卡死**：超时优先砍案例②或④的二次纠错，保③这个高光段。
4. **互动比 PPT 值钱**：鼓励学员说自己场景，现场拿真实需求让 AI 跑，效果最好。
5. **占位符替换**：上台前把讲稿里的 `[姓名]`、`[YYYY-MM-DD]`、`[邮箱/内部 IM]` 填好。

## 常见问题预案

| 学员可能问 | 回答方向 |
|-----------|---------|
| Claude Code 生成的代码能直接用吗？ | 当草稿用，必须复核+跑测试；它是提速不是替你负责 |
| 怎么提高输出质量？ | 给足上下文、拆步骤、设角色、给示例（提示词 4 条） |
| 对话一长 AI 就忘事怎么办？ | 重要信息放 CLAUDE.md/系统提示，或开新对话重发背景 |
| 我们公司能用吗 / 要花钱吗？ | 按公司实际接入方式回答 |
