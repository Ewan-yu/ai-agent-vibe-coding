# 演示脚本：员工信息管理"按部门"贯穿案例

> 配套演讲稿 `presentation_final.md` 幻灯片 14–18。
> 全程围绕**一个真实需求**演：给本项目 `user_service.py` 加"按部门筛选 + 批量导入"。
> 业务顾问段（①②）+ 开发段（③④）是**同一个需求一路打通**，不是孤立 demo。

---

## 一、演示总览

| 段 | 谁演 | 干啥 | 用什么模式 |
|----|------|------|-----------|
| ① 需求澄清 | 业务顾问 | 业务方一句话 → 结构化需求 | `claude -p` 单次 |
| ② 文档产出 | 业务顾问 | → 需求说明 + 用户故事 | `claude -p` 单次 |
| ③ 功能实现 | 开发 | agent 改代码 + 跑测试 | `claude` 交互式 |
| ④ 迭代纠错 | 开发 | 贴报错 → AI 自修 → 跑通 | `claude` 交互式 |

**节奏**：①②约 4 分钟，③约 6–8 分钟，④约 5 分钟。现场跑 AI 有不确定性，**超时就切录屏**（见第六节）。

## 三、开场（约 1 分钟，别长）

## 四、案例①：需求澄清（业务顾问段，约 2 分钟）

### 场景
业务方丢过来一句很随意的话，业务顾问要快速整理成清楚的需求。

### 操作（终端，单次模式）
```bash
claude -p "帮我把下面这段业务方的话，整理成清楚的功能需求和验收点。

原话：「我们想能按部门看人，新来的能一批批录进来，别一个个填。」

请输出：
1. 要做的功能点（分条列）
2. 每个功能怎么算做完了（验收点，要具体、可验证）"
```

### 预期输出（约，AI 每次会有差异）
```
功能需求：
1. 员工增加"部门"字段
   - 验收：每个员工都能标记所属部门，默认"未分配"
2. 按部门筛选员工
   - 验收：选择某部门，返回该部门全部员工；空部门返回空列表
3. 批量导入员工
   - 验收：一次提交多条；合法的入库，不合法的（重复、格式错）跳过并给出原因
```

### 讲解要点
- 一句大白话 → 30 秒变结构化需求，**不用记任何格式术语**，AI 自己组织。
- 业务顾问的价值：**审和改**这份初稿，而不是从零写。
- 如果现场想加点料：追问"顺便估个优先级（MoSCoW）"，看 AI 怎么排。

### 兜底
AI 没响应或网络卡 → 切到提前准备好的截图（上面这段输出存成图片）。话术："正常会出这么一份，我们看下一段。"

## 五、案例②：文档产出（业务顾问段，约 2 分钟）

### 场景
接着①，把整理好的需求直接变成能贴进 wiki 的文档和用户故事。

### 操作（单次模式，承接上一步结果）
```bash
claude -p "基于下面这三条需求，帮我写一份简短的需求说明（功能需求 + 非功能需求），
再给出对应的用户故事（作为…我想要…以便…）。

需求：
1. 员工增加"部门"字段，默认"未分配"
2. 按部门筛选员工
3. 批量导入员工，重复/非法的跳过并记录原因"
```

### 预期输出（约）
```
【需求说明】
功能需求：
- 员工模型新增 department 字段
- 支持按部门查询
- 支持批量导入
非功能需求：
- 批量导入性能：单次 100 条内秒级返回
- 导入失败不影响已成功的数据

【用户故事】
1. 作为 HR，我想要按部门筛选员工，以便快速查看某团队人员。
2. 作为 HR，我想要批量导入新员工，以便入职季不用逐条录入。
3. 作为管理员，我希望导入失败时知道哪条出了问题，以便我修正后重导。
```

### 讲解要点
- 这份东西**可以直接贴进需求文档/wiki**，省掉的是最耗时的"从零起草"。
- 业务顾问日常工作里：**会议纪要、需求文档、用户故事、验收标准、竞品分析**都是这个套路（课后 `quick_reference_guide.md` 有现成模板）。
- 一句话点题：**从"写文档的人"变成"审文档的人"**。

### 兜底
同①，用截图。或现场让 AI 换个语气再生成一次（"改成更口语化的版本"），展示可以反复调。

## 六、案例③：功能实现（开发段，agent 演示，约 6–8 分钟）

> **从这里切到交互式 agent**：终端输入 `claude`（在项目根目录），进入多轮对话。后面全程在里面操作，不用再开别的窗口。

### 场景
开发同学接手，要给系统真正加上"部门"概念。现状：`User` 模型（`src/models/user.py`）压根没有 department 字段。

### 操作（在 `claude` 交互窗口里，粘贴这段）
```
我要给员工系统加"部门"概念。请帮我：

1. 看 @src/models/user.py，给 User 和 UserCreate 加一个 department 字段
   （字符串，默认值"未分配"）
2. 看 @src/services/user_service.py，给 UserService 加两个方法：
   - get_users_by_department(department): 按部门筛员工
   - batch_import_users(users): 批量导入，返回 {成功数, 失败数, 失败明细}
3. 给新方法补单元测试，加到 tests/test_user_service.py
4. 改完跑一遍 pytest tests/ -v，确认原有测试也都还过
```

### 你会看到（agent 的真实行为）
- AI **自己读** `user.py` 和 `user_service.py`（你会看到它调用读文件的工具）
- **自己改**代码：加字段、加方法、加测试
- **自己跑** `pytest tests/ -v`，把结果贴出来
- 如果有小问题，它可能自己就改了再跑

> 这是全场和"网页版 AI"对比最强烈的一段：**它在你项目里直接动手，不用你复制粘贴**。

### 讲解要点（边演边说）
- 注意我**没贴任何代码给它**，我只说了目标和文件位置，它自己去读——这就是 agent 和聊天框的区别。
- `@src/models/user.py` 这种写法是引用文件，省得它猜路径。
- 它改完会**自己跑测试**，这是关键：不是"生成代码就完事"，而是"保证跑通"。
- 这就是 **Vibe Coding**——我用大白话指挥，它在真实代码里落地。

### 兜底（重要）
agent 演示不确定性最高。**提前录屏**：在家完整跑一遍③，录下来。现场如果：
- AI 改错了 / 卡住 / 网络断 → 直接切录屏，话术："我提前跑过一遍，正常是这样——"然后放录屏讲要点。
- 改对了但慢 → 边等边讲解要点，别冷场。

## 七、案例④：迭代纠错（开发段，贴报错自修，约 5 分钟）

> 这是最"真实"的一段。现实里 AI 不会一次完美，**80% 的时间在来回纠错**。

### 场景
③里 `batch_import_users` 大概率有个坑：它如果直接循环调用 `create_user`，遇到重复用户名时，`create_user` 会抛 `ValueError("用户名已存在")`，**一条重复就把整个批量导入搞崩**，测试挂。

### 触发（让 AI 跑批量导入的测试）
在 `claude` 窗口里：
```
跑一下 batch_import_users 的测试，特别是有重复用户名的场景。
```

### 预期（看到测试失败 / 报错）
```
FAILED tests/test_user_service.py::test_batch_import_with_duplicate
- ValueError: 用户名已存在
```

### 关键操作：把报错原样贴回去（不用自己 debug）
```
刚才跑批量导入测试报错了：

ValueError: 用户名已存在

问题在 batch_import_users：遇到重复的会直接抛异常，整个挂掉。
帮我改成：重复的、邮箱格式错的，都跳过并记到失败明细里返回，
不要因为单条失败影响其它。改完重新跑测试。
```

### 你会看到
- AI **自己读报错**、定位到 `batch_import_users`
- 加 `try/except` 把 `ValueError` 兜住，收集到失败明细
- **自己重跑测试**，这次通过

### 讲解要点（这段是全场高潮）
- **我没有自己看懂每一行错误**，我只是把报错复制粘贴回去——这是日常用 AI 写代码最真实的动作。
- 让 AI 自己读报错，**比人去翻译错误信息快十倍**。
- 这也回应了前面原理那页：**AI 会犯错，所以我们写完一定要跑测试**；而跑出错了，正好让 AI 自己修。
- 整个节奏就是：**给目标 → 跑 → 错了贴回去 → 它修 → 再跑 → 通**。

### 兜底
同③，提前录屏。如果现场 AI 一次就改对了没报错（小概率），可以**故意**制造一个：让它"把 get_users_by_department 的大小写改成忽略大小写"，再跑测试看它怎么处理——总之要让大家看到"出错→贴回去→自修"这个循环。

## 八、收尾话术（约 1 分钟）

> "大家看到了，从头到尾就一个需求：业务顾问这边两句话理清需求、出了文档；开发这边让 Claude Code 在真实代码里把功能干完、测试跑通，中间翻车一次，贴个报错它自己修好了。
>
> 三句话带走：第一，你给的上下文越清楚，AI 越靠谱，但它会犯错，结果一定自己复核；第二，Claude Code 是会动手的 agent，先写好 CLAUDE.md；第三，出错了别慌，把报错贴回去让它自修。
>
> 课后两份资料发群里——提示词模板和命令速查，拿走就能用。来，大家提问。"

## 九、常见翻车应对（上台前看一遍）

| 情况 | 应对 |
|------|------|
| AI 输出和预期差很多 | 正常，AI 每次不一样。现场说"我们再让它调一下"，或直接切录屏 |
| 网络/API 卡住超过 20 秒 | 别干等，切录屏，话术："正常流程是这样——" |
| `claude` 命令报错/没装 | 立刻切录屏全程，PPT 照讲，演示部分用录屏 |
| pytest 基线就红 | **这个不能发生**。上台前必须验到全绿，否则③④没法演 |
| 时间超了 | 砍掉②（文档产出）或④的第二次纠错，保③这个高光段 |
| 听众问"我们公司能用吗/要花钱吗" | 准备好一句：说明本地 Claude Code 的获取和账号情况（按公司实际答） |

